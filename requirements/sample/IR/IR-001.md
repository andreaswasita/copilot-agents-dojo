# IR-001 — Document ingest webhook contract

## Contract

- **Endpoint:** `POST /v1/ingest`
- **Auth:** Mutual TLS (client certificate issued by the client CA)
  plus a bearer token bound to the tenant.
- **Body:** `multipart/form-data` with three fields:
  - `tenant` — opaque tenant identifier (string, 8–64 chars)
  - `document` — file part, ≤ 100 MB
  - `sha256` — hex digest of the file part (client-computed)
- **Response:**
  - `202 Accepted` with `{ "ingest_id": "<uuid>" }` within 250ms p95
    when the body validates.
  - `400` if the SHA does not match the file.
  - `413` if the file exceeds 100 MB.

## Why This IR

FR-001 requires classification on ingest, and NFR-001 caps
classification latency at p95 < 2s — which only holds if the upstream
ingest path itself is bounded. This IR pins the upstream contract so
the latency budget downstream is real.
